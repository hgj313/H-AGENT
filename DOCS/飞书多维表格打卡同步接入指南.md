# 飞书多维表格打卡同步 · 接入指南

> 需求：把每天的打卡数据同步到飞书多维表格
> 实现分支：`insurance-ai`（commit `e11aab4`）
> 数据量参考：2026-11-10 单日 451 条打卡记录

---

## 一、为什么不能直接用现有的飞书推送

项目里已经有一套飞书通道（`insurance_agent/tools/feishu_webhook_pusher.py`），
但它**不适合**全量打卡同步：

| 维度 | 现有 webhook 通道 | 本次新增通道 |
|---|---|---|
| 飞书接口 | 自动化流程 webhook | Bitable 开放 API |
| 每次请求 | 1 条 | ≤500 条 |
| 写入能力 | 只能新增 | 新增 / 更新 / 删除 / 查询 |
| 限流 | 10 QPS | 10 QPS，批量摊薄 |
| 推送内容 | 仅「未参保人员」 | 全量打卡记录 |

451 条/天用 webhook 要发 451 次请求，且无法更新已有记录（重复同步会堆重复行）。

> 顺带说明：`feishu-uploader-plugin/` 是多维表格**自动化插件**（附件 PDF → 本地 `/api/upload`），
> 方向与本需求相反，与本次改动无关，两者可并存。

## 二、数据流

```
ERP 打卡接口 ──┐
               ├─→ punch_records 表（唯一数据源，已去重 + 补全项目经理）
MQ 实时推送 ───┘        │
                        ↓
              字段映射层（类型/时间戳转换）
                        ↓
              Bitable 开放 API（批量 500/次）
                        ↓
                飞书多维表格
```

**关键设计：唯一数据源是本地 `punch_records` 表，不再重复调用 ERP。**
原因：这张表已经被全量链路（`coverage_check.sync_punch_data`）和实时链路
（`realtime_punch_consumer`）共同写入并按 `(punch_date, identification_number)` 去重，
两路成果天然汇合，同步时直接读表即可。

## 三、幂等设计

业务主键 = **(打卡日期, 身份证号)**。

新增本地映射表 `feishu_punch_sync_map`：

| punch_date | id_number | record_id | synced_at |
|---|---|---|---|
| 2026-11-10 | 452428196708182024 | recXXXXXX | 2026-11-10 16:45:03 |

- 本地有映射 → `batch_update`（重复同步只更新，不产生重复行）
- 本地无映射 → `batch_create`，成功后回写映射

所以一天内多次同步、服务重启重跑，都不会在飞书表里堆垃圾。

## 四、接入步骤

### 1. 建飞书自建应用

飞书开放平台 → 创建企业自建应用 → 开通权限 **`bitable:app`**
（查看、评论、编辑和管理多维表格）→ **发布版本**（自建应用必须发布后才生效）。

从「应用凭证」页拿到 `app_id` / `app_secret`。

### 2. 建目标多维表格

在飞书里新建多维表格，**列名要与 `field_mapping` 左侧完全一致**。
默认映射：

| 飞书列名 | 本地字段 | 建议列类型 |
|---|---|---|
| 姓名 | member_name | 文本 |
| 身份证号 | identification_number | 文本 |
| 项目名称 | project_name | 文本 |
| 班组 | team_name | 文本 |
| 劳务公司 | supplier_name | 文本 |
| 劳务分类 | category_name | 文本 |
| 审核状态 | examination_status | 文本 / 单选 |
| 年龄 | age | 数字 |
| 电话 | telephone | 文本 |
| 项目经理 | project_manager | 文本 |
| 项目经理手机 | manager_phone | 文本 |
| 项目经理邮箱 | manager_email | 文本 |
| 打卡日期 | punch_date | **日期**（毫秒时间戳） |
| 打卡时间 | punch_time | **日期**（毫秒时间戳） |

> 打卡日期 / 打卡时间必须是「日期」类型。代码会自动转 13 位毫秒时间戳，
> 传字符串会报飞书错误码 1254064。

从表格 URL 取 `app_token`：`https://xxx.feishu.cn/base/bascnXXXX` → 取 `bascnXXXX`。
`table_id` 可以留空用 `table_name` 按名字查（见下方配置说明）。

### 3. 写配置

复制模板并填写：

```bash
cp .feishu_bitable.json.example .feishu_bitable.json
```

```json
{
  "enabled": true,
  "app_id": "cli_xxx",
  "app_secret": "xxx",
  "app_token": "bascnXXX",
  "table_id": "tblXXX",
  "table_name": "",
  "field_mapping": { "姓名": "member_name", "...": "..." }
}
```

- `table_id` 与 `table_name` 二选一：填 `table_name` 则按表名自动查 ID
- `field_mapping` 可整体替换以适配不同列名；未列出的列不写入

### 4. 连通性自检（不写数据）

```bash
curl -X POST http://127.0.0.1:8765/api/feishu-bitable/probe
```

返回会列出目标表的实际列名和 `missing_columns`（配置里声明但表里没有的列）。
**先把 `missing_columns` 清空再正式同步**，否则对应字段会静默丢失。

### 5. 手动触发一次

```bash
curl -X POST "http://127.0.0.1:8765/api/punch/sync-to-bitable"
```

返回 `{"success":true, "total":451, "created":451, "updated":0, "skipped":0, "failed":0}` 即成功。
再执行一次，应该变成 `created:0, updated:451` —— 这就验证了幂等生效。

### 6. 配置定时任务

`data/scheduler_config.json`：

```json
{
  "feishu_sync_time": "16:45",
  "feishu_sync_enabled": true
}
```

16:45 是为了晚于 16:00 的打卡同步任务，等当天打卡数据落库后再同步。

## 五、API 一览

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/feishu-bitable/status` | 查看配置状态（凭证脱敏） |
| POST | `/api/feishu-bitable/probe` | 连通性自检：验 token、列表、字段名 |
| POST | `/api/feishu-bitable/reload` | 热加载 `.feishu_bitable.json`，无需重启 |
| POST | `/api/punch/sync-to-bitable` | 同步某天打卡（`?punch_date=YYYY-MM-DD`，默认今天） |

改完配置调 `/api/feishu-bitable/reload` 或直接 `/api/punch/sync-to-bitable` 都会自动热加载。

## 六、常见问题

**Q: 报 1254041 TableIdNotFound**
`table_id` 填错，或 `app_token` 不是目标表的。跑 `/probe` 确认。

**Q: 报 1254064 DatetimeFieldConvFail**
打卡日期/打卡时间列不是「日期」类型，或代码没转成毫秒时间戳。本项目已自动转换，
检查表里的列类型是否为「日期」。

**Q: 报 1254062 SingleSelectFieldConvFail**
单选列传了表里不存在的选项名。把该列改成「文本」，或在飞书里先加上对应选项。

**Q: 报 1254037 Invalid client token**
`client_token` 必须是 uuid 格式。代码里已用 `uuid.uuid4()` 自动生成。

**Q: 报 99991663 token 失效**
客户端会自动刷新重试一次。若频繁出现，检查系统时钟是否准确。

**Q: 数据没同步过去**
1. `/api/feishu-bitable/status` 看 `enabled` 是否为 true
2. `/api/feishu-bitable/probe` 看 `token_ok` 和 `missing_columns`
3. 查本地是否有当天数据：`punch_records` 表按 `punch_date` 查
