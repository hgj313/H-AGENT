## 教训
1. **SQLite NULL 比较是三值逻辑**：`NULL = NULL` 不是 TRUE，是 NULL；`excluded.end_date >= NULL` 也不是 FALSE，是 NULL。`WHERE` 子句中含 NULL 的行被静默过滤，rowcount=0 没报错——`upsert`/`update` 函数都要用 `COALESCE` 显式兜底
2. **跨批单减保必须放宽匹配**：批单的 `deactivate` 不能用批单号精确相等——同主保单下可能多张批单都有同一人记录。要用主保单号族（中段 18 位）匹配（保单号设计：首位 8/7 主/批，中间 18 位公司+产品族，尾 2 位 serial）
3. **server.py 改动必重启**：`/api/agent/reload` 仅 reload `_GRAPH_CODE_FILES` 列表里的模块；server.py 自身 / 数据库层 / logger 配置等改动必须 kill 进程让 watchdog 拉起新进程
4. **logger 默认沉默**：Python `logging.getLogger(name)` 没配 level 时走 root logger（默认 WARNING），所有 `logger.info/debug` 都不输出。生产代码必须显式 `setLevel(logging.INFO)` + 挂 StreamHandler，否则查问题靠 print 是反模式但 print 被 reload 删掉就找不到日志
