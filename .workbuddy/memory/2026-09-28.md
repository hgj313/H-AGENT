# 2026-09-28 工作日志

## 修复 inline_extractor._ID_REGEX 回归 bug

### 问题
用户上传 `批单_重庆崇茂劳务有限公司_7116013100260120502001.pdf`（利宝保险 inline 格式批单）
含 1 个增保人丁德富，但识别 0 人。PDF 文本明确有：
```
雇员姓名：丁德富，证件号：510228196705309118，方案序号：5，工种描述：砌筑工，用工单位：重庆崇茂劳务有限公司
```

### 根因
2026-09-24 加平安养老 PEAC 适配时，为了支持脱敏 ID（`412702********2432`），
把 `inline_extractor._ID_REGEX` 改成了：
```python
_ID_REGEX = re.compile(r"(\d{6}\*+\d{2,4}[\dXx]?)")  # ✗ 只匹配脱敏
```
该正则**完全不匹配完整 18 位身份证**（`510228196705309118` 这种）。

→ `_ID_REGEX.search(rest)` 找不到 ID → 整人跳过 → **0 人提取**

**回归影响范围**：2026-09-24 之后所有 inline 格式批单（利宝/粤灿等非脱敏格式）均被错误地 0 人提取。
（可能掩盖了之前多个批单的识别问题。）

### 修复
```python
_ID_REGEX = re.compile(r"(\d{17}[\dXx]|\d{6}\*{6,10}\d{2,4}[\dXx]?)")
```
- 优先匹配完整 18 位（regex 引擎从左到右，顺序很重要）
- 然后匹配脱敏（保留原 \* 字符，不反推）

### 回归测试
新增 `tests/test_inline_extractor_id_regex.py`，5/5 全过：
- 完整 18 位 ID（崇茂丁德富）
- 脱敏 ID（平安养老模板）
- 多完整 ID 增保
- 增/减保混合
- 1 完整 + 1 脱敏混合增保

### 端到端验证
curl 上传崇茂劳务批单 → 提取 1 人 → 入库 1 条：
- 丁德富 | 510228196705309118 | 重庆崇茂劳务有限公司
- start=2026-09-26（批单生效日）end=2026-10-17（主保单止期，L1/L2 已补全）
- job=砌筑工 | policy=7116013100260120502001 | company=利宝保险
- status=正常

### 教训
**扩展正则/解析规则时，必须写回归测试覆盖"旧格式+新格式+混合场景"**，避免类似"加了脱敏支持但搞坏了完整 ID"的 bug。

类似陷阱可能在其它 extractor 也存在。需检查：
- `table_extractor._ID_REGEX` / `_MASKED_ID_PATTERN_FULL`
- `metadata_extractor._ID_PATTERN`

### 1 处 DB 约束修复

**问题**：`idx_person_name_id` 残留 **PARTIAL UNIQUE INDEX** `ON (name, id_number) WHERE id_number != ''`，
导致同一员工跨保单入库时（如胡志福在利宝 7116013100260082838002 和阳光 HGC... 都被保）抛 IntegrityError。

**修复**（`database.py._migrate_drop_person_name_id_index`）：
```python
cursor.execute("DROP INDEX IF EXISTS idx_person_name_id")
cursor.execute("CREATE INDEX IF NOT EXISTS idx_person_name_id ON insurance_personnel(name, id_number)")
conn.commit()
```
删除 UNIQUE 约束，保留普通 INDEX。表级 `UNIQUE(id_number, policy_number)` 已足够保证唯一性。

### 教训
1. **入库层缺 UNIQUE 约束**:`insurance_personnel` 表目前只有 `(id_number, policy_number)` UNIQUE,没有 `(name, id_number)` UNIQUE,所以重复入库会被默默接受。
2. **建议补强**:`database.py` 加 `_migrate_add_person_name_id_partial_unique`:
   ```sql
   CREATE UNIQUE INDEX IF NOT EXISTS idx_person_name_id_partial
   ON insurance_personnel(name, id_number)
   WHERE id_number != ''
   ```
   注:这条要小心——9-28 之前已删掉的 `idx_person_name_id` UNIQUE INDEX 就是因为"同人跨保单"是合法场景。但同人**同保单**不该有重复,所以 PARTIAL UNIQUE WHERE `policy_number IS NOT NULL` 是合适折中。
