## 关键教训
1. **不能把 table_extractor 工种提取改成 pre_region 优先**：pre_region 边界混入前一人 post 数据（含前人工种）+ 表头"用工单位"，导致利宝第1人误报"计划用工"。正确做法是保持 post 优先 + 排除噪声词（"建筑工"来自"建筑工程"）。
2. **"建筑工"误匹配**：`_JOB_PATTERN` 贪婪匹配"建筑工程"里的"建筑"+"工"→"建筑工"。用 `candidate=="建筑工" and region[match.end()]=="程"` 精确排除（后面紧跟"程"说明是"建筑工程"不是工种）。
3. **北部湾第1页"保险单主页"含"证件号码：91500115MA5U6FB90C"**（被保险人统一社会信用代码），旧 `_is_real_list_page` 仅凭"证件号码"就误判为清单页。用"统一社会信用代码"关键词排除。

## 2026-09-22 下午：北部湾保单号"没提取出来"问题排查

### 现象
用户反馈重庆廊虎商贸保单"保单号没有提取出来"，API 上传返回 policy_number=None。

### 根因（重要教训）
代码本身正确（离线测试 policy_number='804147201322026001245' 正常提取），但**服务端跑的还是旧代码**。

`/api/agent/reload` 热重载只重建 graph 内部节点，**不更新 server.py 顶部的 `from ... import` 模块引用**（Python import 缓存）。所以改了 extractors/tools/parsers 层文件后，即使 agent/info 显示 graph_signature 已重建、rebuild_pending=false，服务端实际仍在用旧的模块代码。

⚠️ 补充记忆里已有的老教训：**改任何被 server.py `from import` 引用的模块后，必须 kill server.py 进程让 watchdog 重启，而不是靠 /api/agent/reload**。reload 只对"纯 graph 节点内部逻辑"有效，对 server.py 已 import 的模块引用无效。

### 排查过程
1. 离线 pipeline 测试 → 保单号正确提取 ✅（排除代码问题）
2. API 上传 → policy_number=None ❌（定位到服务端环境问题）
3. agent/info 显示 graph 已重建，但实际 server.py import 缓存未刷新
4. kill 14200 → watchdog 重启（PID 43548）→ 重新上传 → 保单号正确 ✅

### 验证结果
DB 3 人最终状态正确：吕治国/李国会/李国高，job_title=油漆工，policy_number=804147201322026001245，2026-10-01~2027-09-30，北部湾财产保险。

### 注意
- 服务刚重启后有 `llm_available=false` 窗口期，此时上传会返回空结果，等几秒再传。
- /api/upload 响应结构是 `{success, results:[{...}]}`，不是顶层字段，测试脚本要读 `results[0].policy_number`。
