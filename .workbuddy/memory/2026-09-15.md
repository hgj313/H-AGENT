## 4. 3 个预防建议实施（提交 90c96d1，用户原话"采纳建议"）

### 建议1: 上传顺序拦截（web_app/server.py `_process_single_pdf`）
- 检测到 `fname_info.policy_type == "批单"` 且 warnings 含「未找到对应主保单」或「主保单号不一致」
- 直接 return error「批单主保单缺失/不匹配：{msg}」阻断脏数据入库
- 配合 404-style 错误让用户立即看到提示，而不是默默入库错数据

### 建议2: 保单号前缀兼容校验（policy_library.py）
- 新增 `_policy_numbers_compatible(batch_no, main_no)` 静态方法
- 利宝规则：batch `71XX` 与 main `81XX` 中间 18 位（第 2-19 位）必须相同
  - 第 1 位：7=批单 / 8=主保单
  - 第 2 位：必须一致（保单类型码）
- `find_main_policy()` 调用 `find_main_policy_by_company()` 后再校验前缀兼容性
- 不兼容 → 返回 None，触发建议1的拦截
- 兜底防止 validator 漏网（多层防御）

### 建议3: UI 日期异常高亮（web_app/static/index.html）

- JS：`checkDateAnomaly(p)` 检查 start>end / start_missing / end_missing
- 命中位置：
  - 识别结果表（上传后立即可见）
  - 人员清单页（数据库中已有人员）
- 人员清单筛选条新增「⚠ 仅日期异常」按钮
- 页面标题显示异常计数徽章（0 时隐藏）
