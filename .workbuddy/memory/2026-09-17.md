## 1. 中国人寿"在保名单"绿洲团体意外险 - 新增 block_kv 格式支持

### 用户反馈
- 上传 `D:\desk\吉盛\在保名单批次一 (1).pdf`："分析一下该类型文件的保单。提取出人员信息。以后遇到这种类型的能完成提取。"
- 同目录下还有 10 份相关文件：批次二、7-9 月增人/减人/替换人批单

### 格式识别特征
- 表头："**有效被保险人清单**" / "**在保名单**"
- 强特征：**"汇交号/保险合同号：22位字符"** + "**被保人顺序号**" + "**要约状态：生效**"
- 投保人："投保人名称：XXX有限公司"
- 整体期限：两条独立字段「**保险合同生效日期**」「**保险合同满期日期**」（顺序不固定，本次 PDF 是「满期→生效」）
- 每人是独立"块状键值对"：
  - 序号:1 姓名：刘典斌
  - 被保人类型：主被保险人 / 性别：男 / 出生日期：YYYY-MM-DD
  - 证件类型及号码：身份证:42108119710618563X
  - 职业名称：电路安装及维（跨行）修工人
  - 生效日期：YYYY-MM-DD 终止日期：YYYY-MM-DD（**逐人日期**，与中国人寿财险整体期限不同）
- 跨行干扰严重："身份\n证" / "证件\n类型\n及号\n码：" / "序\n号：1" / "电路安装及维\n修工人"

### 与已有格式的关键差异
| 维度 | table（利宝保单等） | block_kv（中国人寿在保名单）✅ 新增 |
|---|---|---|
| 结构 | 整张表 | 每人独立块 |
| 日期 | 整体期限（一份保单一个期间） | **每人有独立生效/终止日** |
| 字段顺序 | 标准表头（序号/姓名/身份证等列对齐） | 键值对，无对齐 |
| 跨行 | 偶发 | 大量（证件/序号/职业/出生日期等都会跨行） |

### 实现要点
1. **新 extractor**：`insurance_agent/extractors/block_kv_extractor.py`（`BlockKVExtractor`）
   - `is_match(all_text)`：检测有效被保险人清单/汇交号/被保人顺序号+要约状态 等强特征
   - `_clean_text(text)`：身份\n证→身份证 / 证件\n类型\n及号\n码→证件类型及号码 / 序号\n号:N→序号:N / 多空白合并为单空格
   - `_extract_overall_period(text)`：双 regex list（顺序1：生效→满期 / 顺序2：满期→生效），单 regex 用非捕获组会有歧义
   - `_parse_person_chunk`：姓名→身份证（is_valid_chinese_id 校验）→出生日期（缺失时从身份证号兜底）→性别→职业（**捕获到下个字段标签，避免 `\S+` 在跨行空格截断**）→逐人起止日期
2. **格式分发**：`metadata_extractor_node.py` 加 `_BLOCK_KV_MARKERS` 和 `format_hint == "block_kv"` 分支
3. **保单号正则**：`_extract_policy_number` 主保单 patterns 加 "汇交号[：:\s]*([A-Za-z0-9]{20,30})" 兼容 22 位绿洲团体意外险号
4. **整体期限正则**：`date_parser.py` 新增 `_extract_block_kv_period` 函数（避开顺序歧义，先收集所有"保险合同XX日期"取值再 min/max）
5. **服务端集成**：
   - `extractors/__init__.py` 导出 `BlockKVExtractor`
   - `personnel_extractor_node.py` 加 `block_kv_extractor` 注入 + `format_hint == "block_kv"` 分支
   - `web_app/server.py _GRAPH_CODE_FILES` + `_reload_graph_dependencies` 加 `block_kv_extractor.py` + `date_parser.py`

### 关联 bug 修复（block_kv 路径暴露）
- **pymupdf_parser.py `_detect_insurance_company` 重叠关键词问题**：之前按命中次数排序，"中国人寿"被"中国人寿财产保险"包含 2 次也计 2 次，但中国人寿品牌名 PDF 实际只出现"国寿"2 次——修复为按 `max_pattern_len` 优先（最长关键词命中过则优先选最长），避免"中国人寿财产保险"抢走"中国人寿"命中的倒挂现象

### 教训 / 防复发
1. **跨行干扰的字段提取不要用 `\S+`** —— 必须用 lookahead 捕获到下个字段标签边界
2. **关键词数量加权有重叠风险** —— 必须配合「最长关键词命中优先」才能区分 "中国人寿财产保险" 与 "中国人寿"
3. **品牌名与全称并存** —— 中国人寿品牌名 PDF 只写"国寿"，主保单 keywords 需双轨配置（国寿 + 中国人寿）
4. **server.py 模块级 `from X import Y` 在 reload 后不更新** —— 需要重启服务，或改用 `X.Y` 全限定引用；本次通过 ctypes TerminateProcess + watchdog 自启的标准路径解决

### 格式分析逻辑（模板特征）
1. **双栏表格**：左栏「增加被保险人」= 姓名+个人编号+证件类型+证件号码+险种+保额+标准保费；右栏「减少被保险人」= 仅姓名+个人编号（**无证件号码**）。
2. **日期在身份证号之前**（pre_region）：生效日/终止日用 `YYYY/MM/DD`（中国人寿特有 `/` 分隔），须 `date_parser` 加 `/` 支持。
3. **变动类型列**：增/减/替换；"同期增减"="同时增+减"（替换语义）。per-row 识别，文件级 mod_type 仅 fallback。
4. **噪声标签**：页脚「受理时间：2026年07月31日」会污染起期 → 预处理剔除「受理时间/受理日期/制单时间」。
5. **工种误识**：列名「增加主被保险人/减少被保险人/同期增减」会被工种正则误配 → `_VARIATION_NOISE` + `_TABLE_HEADER_KEYWORDS` 双重黑名单。

### 代码改动（相对 block_kv 提交后增量）
- `tools/date_parser.py`：`_DATE_PATTERN` 加 `/` 分隔符；`_OVERALL_PATTERNS` 4 条主正则 `-` 分隔兼容 `/`
- `extractors/table_extractor.py`：
  - pre_region 日期搜索（ID 之前 200 字符，截断到上一个身份证号之后）
  - `_detect_row_modification_type(region)`：同期增减/替换/置换→增保 > 减少/删除→减保 > 增加→增保
  - `_VARIATION_NOISE` / `_TABLE_HEADER_KEYWORDS` 工种黑名单 + 表头列名过滤
  - 预处理剔除「受理时间/受理日期/制单时间」
