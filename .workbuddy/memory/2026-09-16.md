- 批单004 PDF 文本"自2026年09月13日零时起生效"被 `metadata_extractor` 提取到 `working_memory["endorsement_effective_date"]`

### 同类问题排查结果

#### Bug A 反序数据全库扫描


#### Bug B 批单 policy_number 全错为 81（63 条）

## 4. 段小平 insurance_company 错识为"黄河财险" — 复核遗漏字段暴露

### 用户反馈
- "段小平 512928196510276918 身份证 1965-10-27 杭州班王建筑劳务有限公司重庆分公司 正常 2026-09-12 2027-01-14 铺装工 **黄河财险** 6130101040320260000001-088 — 系统数据中段小平数据显示还是黄河财险呢"
- 用户截图显示 `insurance_company` 字段存的是"黄河财险"

### 根因（3 层缺陷叠加）
1. **`_COMPANY_PATTERNS` 缺"华安"关键词**（但有"黄河"）—— PDF 文本提到"黄河"被命中
2. **`_detect_insurance_company` 首次命中策略** —— 多个公司关键词同存时按字典序先匹配到"黄河"，无加权
3. **无保单号→保险公司号段映射兜底** —— 文本识别被模板残留条款带偏

### 上轮复核为何没发现
- 上轮"数据复核"只核对了 7 条记录的**姓名 / 身份证 / 起止日期**，**漏验了 insurance_company 字段**
- 当时已发现 MEMORY 把保险公司误记为"黄河"，修正了 MEMORY，但没意识到 DB 字段也是错的
- **教训：数据复核要逐字段验证，不能"挑几个核心字段看对就以为全对"**

### 修复（3 层防御）

**L1 `_COMPANY_PATTERNS` 加华安**
```python
"华安财产保险": ["华安财产保险", "华安保险", "华安财险", "Sinosafe"],
```

**L2 `_detect_insurance_company` 按命中次数加权**
```python
hits = []
for company_name, patterns in self._COMPANY_PATTERNS.items():
    count = sum(all_text_lower.count(p.lower()) for p in patterns)
    if count > 0:

hits.sort(key=lambda x: x[0], reverse=True)
return hits[0][1] if hits else "unknown"
```

1. **白名单完整性**：`_COMPANY_PATTERNS` 漏一个公司就可能误识别
2. **加权而非首次命中**：PDF 模板残留/条款引用会带偏文本识别
